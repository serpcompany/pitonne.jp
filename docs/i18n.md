# Internationalization (i18n)

pitonne.jp supports English (default) and Japanese via a subdirectory URL structure.

## URL Structure

```
pitonne.jp/                      → English (default)
pitonne.jp/ja/                   → Japanese
pitonne.jp/services/iv-therapy/  → English service page
pitonne.jp/ja/services/iv-therapy/ → Japanese service page
```

English URLs have no `/en/` prefix. If someone visits `/en/...`, a 301 redirect strips it to `/...`.

## Architecture

- **Routing:** English pages are real bare routes under `app/(en)/`. Japanese pages are generated from `app/[locale]/` with `nonDefaultLocales`, currently only `ja`.
- **No middleware:** English is the default physical route structure. `/en/...` is handled by Cloudflare Pages redirects, not by an internal rewrite.
- **No external i18n library.** Custom lightweight solution: locale config, JSON dictionaries, locale-aware data loading.

### Key Files

| File | Purpose |
|---|---|
| `lib/i18n/config.ts` | Locale types, constants (`locales`, `Locale`, `defaultLocale`) |
| `lib/i18n/dictionaries.ts` | Dictionary loader (`getDictionary(locale)`) |
| `lib/i18n/dictionaries/en.json` | English UI strings (nav, footer, buttons, headings) |
| `lib/i18n/dictionaries/ja.json` | Japanese UI strings |
| `app/(en)/` | Bare English route wrappers |
| `app/[locale]/` | Locale-aware page implementations and `/ja` routes |
| `public/_redirects` | Redirects `/en/*` to bare English paths |
| `lib/seo.ts` | `localizedCanonicalUrl()`, `localizedHreflangAlternates()`, `localizedPath()` |
| `lib/data/routes.ts` | `localizedRoute(path, locale)`, `getAreaNavigation(locale)` |

## Content

### Markdown Content (Services & Blog)

English and Japanese content are stored as sibling markdown files:

```
content/
  services/
    iv-therapy.md              ← English
    ja/
      iv-therapy.md            ← Japanese (same filename, ja/ subdirectory)
  blog/
    iv-therapy-for-fatigue.md  ← English
    ja/
      iv-therapy-for-fatigue.md ← Japanese
```

Slugs, canonical paths, category slugs, and all identifier fields stay in English across both versions. Only human-readable text (title, description, body, FAQs, benefits, etc.) is translated.

### Data Layer

All data functions accept an optional `locale` parameter defaulting to `'en'`:

```ts
getService("iv-therapy", "ja")       // Japanese service data
getAllBlogPosts("ja")                 // Japanese blog posts
getBlogPostBySlug("iv-therapy-for-fatigue", "ja")
getServiceCategorySections("ja")     // Returns Japanese category titles
getBusinessInfo("ja")                // Japanese business description + day names
```

### UI Strings

Header, Footer, and page chrome use JSON dictionaries:

```ts
const dict = getDictionary(locale)
dict.nav.services    // "サービス"
dict.footer.openHours // "営業時間"
dict.common.contactUs // "お問い合わせ"
```

## Translation Workflow

### Translating New Content

```bash
# Translate all missing content (only creates files that don't exist in ja/)
npx tsx scripts/translate-content.ts

# Translate a single file
npx tsx scripts/translate-content.ts --file content/blog/new-post.md

# Force re-translate everything
npx tsx scripts/translate-content.ts --force

# Preview without writing
npx tsx scripts/translate-content.ts --dry-run
```

Requires `DEEPL_API_KEY` in `.env`. Uses the DeepL API with header-based auth.

### After Translation

Translated files are committed to git. They are the source of truth after generation. Human editors can refine translations by editing the Japanese markdown files directly.

## Adding a New Page Route

1. Create the locale-aware implementation under `app/[locale]/your-page/page.tsx`.
2. Add a thin English wrapper under `app/(en)/your-page/page.tsx` that passes `locale: "en"` to the shared implementation.
3. Extract locale from params in the shared implementation: `const { locale } = await params`.
4. Load dictionary: `const dict = getDictionary(locale as Locale)`.
5. Add hreflang to metadata: `alternates: localizedHreflangAlternates("/your-page/", locale as Locale)`.
6. Make all internal `<Link href>` locale-aware: `localizedRoute("/target/", locale as Locale)`.
7. For localized route static params, generate only non-default locales and disable dynamic params:
   ```ts
   export const dynamicParams = false

   export async function generateStaticParams() {
     return nonDefaultLocales.flatMap(locale => existingParams.map(p => ({ locale, ...p })))
   }
   ```

## SEO Signals

Every page includes these signals for Google:

| Signal | Implementation |
|---|---|
| `<html lang>` | `"en"` or `"ja"` per locale |
| `hreflang` | Bidirectional `en`, `ja`, `x-default` on every page |
| Canonical URL | Self-referencing. English: no prefix. Japanese: `/ja/` prefix |
| `og:locale` | `en_US` or `ja_JP` |
| Sitemap | Both locales with `alternates.languages` cross-references |
| JSON-LD `inLanguage` | Set on all structured data (MedicalBusiness, WebSite, Service, BlogPosting) |
| JSON-LD `availableLanguage` | MedicalBusiness and WebSite list both English and Japanese |
| JSON-LD `translationOfWork` / `workTranslation` | BlogPosting schemas link English and Japanese versions as translations |

## Pages NOT Localized

Per business decision, these pages serve English content for both locales (they still have the `/ja/` route for routing consistency):

- `/legal/*` (privacy policy, terms, disclaimer)
- `/videos/*` and `/watch/*`
